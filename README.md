# Real-time ECG classification with a signal-quality gate (PTB-XL)

> **Result:** a 1D ResNet that runs in **8.9 ms p95 on a laptop CPU** reaches **0.932 ± 0.001 macro AUROC** on PTB-XL fold 10 (published benchmark ≈ 0.93), beating a strong feature baseline (0.924 ± 0.001) mainly on MI: **sensitivity 0.80 vs 0.75 at 90% specificity**. The autoencoder quality gate reliably refuses grossly corrupted signals, but it does **not** detect PTB-XL's own annotated noise (AUROC 0.62), and rejecting by it does not improve accuracy.

A CPU-deployable multi-label classifier for the 5 PTB-XL diagnostic superclasses: NORM (normal), MI (myocardial infarction), STTC (ST/T change), CD (conduction disturbance) and HYP (hypertrophy). An autoencoder trained only on clean ECGs scores every input first. Inputs above its reconstruction-error threshold get `{"status": "low_quality"}` instead of a diagnosis.

**Questions**
1. Under a fixed CPU budget (20 ms p95 per 10 s record, batch 1, ONNX Runtime, 4 threads), which architecture is most accurate: 1D ResNet, BiLSTM or Transformer?
2. Can an autoencoder trained only on clean ECGs flag noisy recordings, judged against PTB-XL's own noise annotations, and does rejecting them improve accuracy on what remains?

**Answers**
1. **A convolutional network.** The full 6.3M-parameter ResNet already runs in under 10 ms and is the most accurate model under the budget. A BiLSTM shrunk to fit ties it within seed noise. Transformers trail even the feature baseline.
2. **Only for gross corruption.** The gate catches heavy synthetic noise and baseline wander, and annotated electrode problems (AUROC 0.93). It barely detects the mild noise PTB-XL annotators flagged, and that noise costs the classifier only 0.007 AUROC anyway. Rejecting by reconstruction error makes accuracy slightly *worse* than rejecting at random.

## How to run (3 commands)

```bash
make setup data                                  # install, fetch PTB-XL 1.0.3 (S3 mirror, 100 Hz) and build the cache
make baseline c1 c2 c3 ae                        # all training runs, 3 seeds each (GPU; see Compute)
make c4c5 c6 gradcam failures export report      # analysis, figures, ONNX export, results tables
```

`make test` runs 32 tests on synthetic data, so no download is needed. Two steps need no data but must run on the deployment CPU: `make c2-sweep` (before training) and `make latency serve-latency` (after). `make serve`, `make demo` and `make loadtest` run the API, the streaming demo and the load test.

### Q1: accuracy under the 20 ms CPU budget

| Model (fits 20 ms p95) | Test macro AUROC | MI sens. @ 90% spec. | Macro F1 | CPU p95 | Size |
|---|---|---|---|---|---|
| **ResNet, pos_weight (deployed)** | **0.932 ± 0.001** | 0.799 ± 0.020 | 0.751 ± 0.002 | 8.9 ms | 25.2 MB |
| ResNet | 0.931 ± 0.001 | 0.804 ± 0.020 | 0.749 ± 0.004 | 8.8 ms | 25.2 MB |
| ResNet-34 (C2, deeper) | 0.930 ± 0.001 | 0.784 ± 0.007 | 0.748 ± 0.002 | 16.9–18.8 ms | 47.7 MB |
| BiLSTM-192 (C2, shrunk) | 0.929 ± 0.001 | 0.796 ± 0.006 | 0.754 ± 0.003 | 19.6–20.0 ms | 4.8 MB |
| Transformer 8×256 (C2) | 0.922 ± 0.000 | 0.746 ± 0.010 | 0.745 ± 0.002 | 4.3 ms | 25.7 MB |
| *Baseline: features + gradient boosting* | *0.924 ± 0.001* | *0.747 ± 0.007* | *0.746 ± 0.003* | — | — |
| *Full BiLSTM (C1, over budget)* | *0.931 ± 0.001* | *0.797 ± 0.005* | *0.753 ± 0.009* | *32.6 ms* | *8.5 MB* |

- **Baseline first.** Handcrafted features (lead statistics, band powers, RR intervals, a per-lead median beat) with gradient-boosted trees reach 0.924, within 0.01 of the benchmark. The deep models' AUROC gain is real (about 8× the seed std) but small. The clinically meaningful gain is MI sensitivity: 0.80 vs 0.75 at 90% specificity, about 28 more of the 550 test MIs caught.
- **"Largest model that fits" was the wrong selection rule.** The C2 sweep picked the deeper ResNet-34 because it was the biggest variant under budget. It is slower and slightly *less* accurate than the 6.3M ResNet, which already fits in 9 ms. The deployed model is therefore the best **validation** AUROC (0.9349) among budget-fitting runs.
- **The BiLSTM sits on the line.** Shrinking it from hidden 256 to 192 costs only 0.002 AUROC, but its p95 measured 19.6 ms in one session and 20.0 ms in another. That's no safety margin.
- **Transformers underperform here.** 25-sample patches put a whole QRS complex inside one token, and 17k records give no local-shape prior. Size helps (0.914 → 0.922), but it's still below the baseline. They were not re-tuned after seeing test results.
- **Ablations.** Class pos_weight: +0.001 (within noise). Bandpass 0.5–40 Hz: no change (validation 0.9342 vs 0.9344) and about 5× the seed spread; it stays off, as configured from the start.

![coverage vs accuracy](reports/figures/c5_coverage_accuracy.png)

- **PTB-XL's annotated noise is mostly harmless to the classifier** (−0.007 AUROC), so even perfect detection of it, the oracle column, buys only +0.001.
- **The gate flags the wrong records for accuracy purposes.** High reconstruction error picks out *unusual* ECGs, not *misclassified* ones. Removing them lowers AUROC, while random removal doesn't. The likely explanation is that unusual records are often strongly abnormal and easy to classify; this hypothesis was not tested further.
- **It works as a guard against broken input (C6).** It flags 100% of records with ≥ 0.1 mV of added Gaussian noise and 97% with ≥ 0.5 mV of baseline wander. It is also conservative: at 0.1 mV the classifier would only have lost 0.01 AUROC. Its blind spot is **dead leads**: 6 of 12 leads flat-lined are flagged only 18% of the time, because zeros are easy to reconstruct.

## Failure analysis

From `make failures` on the deployed model (`reports/tables/failures_c1_resnet1d_posweight.md`, seed 0, frozen fold-9 thresholds):

| Class | Positives | Missed (FN rate) | False alarms | AUROC | F1 |
|---|---|---|---|---|---|
| NORM | 963 | 107 (11%) | 171 | 0.952 | 0.860 |
| MI | 550 | 93 (17%) | 182 | 0.936 | 0.769 |
| STTC | 521 | 89 (17%) | 181 | 0.937 | 0.762 |
| CD | 496 | 135 (27%) | 84 | 0.927 | 0.767 |
| **HYP** | 262 | **114 (44%)** | 89 | 0.914 | **0.593** |

- **Hypertrophy is the weakest class.** It is the rarest class, it is defined largely by voltage criteria, and per-lead standardization partly removes absolute amplitude. Examples of confident misses: ecg_id 20369, 1745 and 9299 (HYP only, predicted NORM at p ≥ 0.98).
- **Multi-label records are hard.** 2-label records score 0.890 AUROC vs 0.929 for single-label ones. The most confidently missed STTC cases are mostly MI|STTC records (e.g. 18019, 17404, 15259): the model reports the MI and misses the accompanying ST/T change.
- **Older patients:** 0.911 AUROC for age 75+ vs 0.934 under 40.
- **Sex gap:** **0.941 for men vs 0.925 for women.** That's larger than the gap between architectures, and it is not addressed here.
- **Probable label errors among the "failures."** ecg_id 10887 is labelled NORM but gets p(NORM) = 0.03 and p(MI) = 0.98. ecg_id 7895 is labelled MI with p(MI) = 0.01 and p(NORM) = 0.99. These need a cardiologist's re-read before being counted against the model.
- **Grad-CAM shows no evidence of ST-segment focus.** Over 10 confident true-positive MIs, the CAM mass inside estimated ST windows is 1.02× chance (`reports/figures/gradcam_mi.png`). A plausible reason is that most PTB-XL MIs are *old* infarcts, recognised by Q waves inside the QRS rather than by ST changes. With 10 cases at coarse resolution, this is "no evidence", not proof.

## Limitations

- **The noise labels are weak ground truth.** The four metadata noise columns were annotated inconsistently, which bounds the measurable gate AUROC.
- **The gate measures how unfamiliar a signal is, not how likely the classifier is to be wrong.** It also misses flat-lined leads. A production version would add rule-based checks (flat line, saturation, amplitude range) and calibrate rejection against classifier error, not reconstruction error.
- **Latency depends on the hardware.** All numbers come from one Apple M4 laptop and vary by up to 3 ms between sessions. The budget-based selection must be redone for another CPU.
- **100 Hz only.** The 500 Hz records might help QRS-shape classes (CD, HYP); this was not tested.
- **Uncalibrated thresholds.** Thresholds maximize per-class F1 on fold 9. Outputs are not calibrated probabilities, and a clinical threshold policy would need clinicians.
- **One dataset, no external validation.** The model has a measurable sex gap and lower performance in elderly patients.
- **Research prototype, not a medical device.**

## Deployment

| | Measured (Apple M4, 4 threads unless noted) |
|---|---|
| Classifier (ONNX, 7 sliding windows) | p50 9.0 ms / p95 9.7 ms, 25.2 MB |
| Quality-gate autoencoder (ONNX) | p50 1.4 ms / p95 1.6 ms, 1.6 MB |
| Full pipeline (gate + classifier) | **p50 11.9 ms / p95 13.6 ms** |
| HTTP `POST /classify`, 1 user | 37.8 req/s, p50 21 ms / p95 22 ms |
| HTTP, 8 concurrent users (1 worker) | **90.7 req/s**, p50 74 ms / p95 110 ms, 0 failures |
| Docker serving image | **303 MB** (linux/amd64, no PyTorch) |

About 9 ms of the HTTP time is parsing 12,000 JSON floats. A binary payload would roughly halve single-request latency.

```bash
make export                       # artifacts/{classifier,autoencoder}.onnx + meta.json, ONNX vs PyTorch parity checked
make serve                        # or: make docker (serving image, linux/amd64)
make demo                         # streaming demo: 1 s chunks, rolling 10 s window, live decision
make loadtest                     # locust, requests/sec on CPU
```

`POST /classify` takes a 12 × 1000 array (mV, 100 Hz, leads I, II, III, aVR, aVL, aVF, V1–V6). It returns either
`{"status": "ok", "labels": [...], "probabilities": {...}, "reconstruction_error": ..., "latency_ms": ...}` or
`{"status": "low_quality", "message": "signal quality too low", ...}`. Malformed input gets a 422.

**Docker.** `serve/Dockerfile` contains only the serving side: FastAPI, ONNX Runtime, the two ONNX models and `meta.json` (normalization statistics, per-class thresholds, gate threshold). There's no PyTorch and no training code in it. `make docker` builds `linux/amd64` by default, so an image built on an Apple Silicon Mac runs on x86 servers. The port comes from `PORT`.

**Verified in CI.** `.github/workflows/docker.yml` builds the image and starts it. It then requires three responses: a clean fold-10 ECG (ecg_id 17690) must come back `ok` with exactly STTC, CD and HYP; the same record plus 0.3 mV of noise must be refused; and malformed input must get a 422.

**Hugging Face Space.** `bash scripts/hf_space_bundle.sh` assembles the same image as a Hugging Face Docker Space (card in `deploy/huggingface/`).

## Method

| | |
|---|---|
| Data | PTB-XL v1.0.3 (CC BY 4.0), 100 Hz, 12 × 1000 per record. 21,388 records kept; 411 without a diagnostic superclass were dropped (benchmark protocol). |
| Splits | `strat_fold` 1–8 train (17,084) / 9 validation (2,146) / 10 test (2,158), patient-wise. Normalization is fitted on folds 1–8 only and stored in each checkpoint. |
| Training | Random 2.5 s crops with amplitude scaling, Gaussian noise, baseline wander and lead dropout. BCE-with-logits, AdamW, one-cycle schedule, ≤ 50 epochs, batch 128, early stopping on validation macro AUROC (patience 8), 3 seeds. |
| Inference | 7 sliding 2.5 s windows (stride 1.25 s), probabilities averaged. The exported ONNX graph includes the windowing. |
| Models | ResNet 1D (6.3M params), BiLSTM 2×256 (2.1M), patch Transformer 4×128 (0.84M), conv autoencoder 12 → 128×125 → 12 (~0.4M). |
| Gate | Per-record reconstruction MSE. Threshold = 95th percentile of clean fold-9 errors. |
| Decisions on fold 9 only | Early stopping, F1 thresholds, MI operating point, gate threshold, deployed model. Fold 10 is read only for final scoring and analysis. Caveat: test results had been viewed before the deployment candidates were compared; the rule was validation-only, and validation and test agree. |
| Tracking | MLflow (`tracking.backend`). Per run, `runs/<name>/seed<k>/` holds the resolved `config.yaml`, `metrics.json` and `preds.npz`; checkpoints are kept out of git except the deployed one. |

## Using this package from another project

Project 3 reuses this pipeline and classifier as its evaluator by **installing** this repo, so there is exactly one PTB-XL loader:

```bash
pip install "ptbxl-ecg @ git+https://github.com/oladri-renuka/ecg-quality-gate.git@v0.1.0"
```

```python
from ptbxl_ecg import Evaluator, load_cache, make_splits

X, Y, meta = load_cache("data/processed")    # built by: python -m ptbxl_ecg.data.ptbxl --root <ptb-xl dir> --out data/processed
split = make_splits(meta)                    # folds 1-8 / 9 / 10, identical to this repo
ev = Evaluator("runs/c1_resnet1d_posweight/seed0/best.pt")   # the deployed checkpoint, tracked in this repo
ev.evaluate(X[split.test], Y[split.test])    # raw mV in; the checkpoint's own normalization and frozen thresholds
```

- `PIPELINE_VERSION` is stamped into the cache and every checkpoint, so mismatches raise `PipelineVersionError` instead of scoring silently through a different pipeline.
- The public surface is `ptbxl_ecg.__all__`: `load_cache`, `make_splits`, `Evaluator`, `build_model`, `load_checkpoint`, `preprocess` and the label/lead constants.
- **Not provided in v0.1.0:** an embedding function, and `load_ptbxl` / `embed` / `evaluate` aliases.

## Compute

Prototyped locally (Apple M4). The final sweep ran on one RunPod **A40**: 75 runs (25 experiments × 3 seeds), **5.8 GPU-hours of logged training time** (5.78 h classifiers, 0.06 h autoencoder) plus 0.1 h of CPU time for the baselines. Data download, analysis and idle time are not included. PTB-XL was fetched from PhysioNet's public S3 mirror, because physionet.org served about 1 MB/min to the pod.
